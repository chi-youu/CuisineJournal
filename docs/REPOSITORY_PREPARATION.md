# 仓库提交范围

准备工具只检查和复制源码，不会创建远程仓库、提交、推送或发布模组；这些操作须按维护者授权分别执行。源码推送也不会更新Release附件。

## 提交

源码/资源/测试、Gradle 脚本和 Wrapper、许可证/署名、功能与配置文档、架构、可复用工具及 CI。
.gitignore 使用根目录允许清单；新增根文件、工具或文档时需要明确允许，防止临时文件混入。

## 仅留本地

| 内容 | 原因 |
| --- | --- |
| .gradle*、build*、run*、logs/、IDE/Python 缓存 | 可生成的机器副产物 |
| 根目录构建日志、错误输出 | 不是源码，关键证据本地保留 |
| libs/、反编译 JAR/源码 | 第三方依赖和调查产物不随仓库再分发 |
| AGENTS/CLAUDE、CURRENT_STATUS、DECISIONS、PENDING | 本机协作、私有路径和开发记忆 |
| 旧 *_STATUS.md、CODE_AUDIT、docs/history/ | 开发过程及旧结论，不混进用户入口 |
| docs/compatibility/、技能草案 | 实例安装快照与内部调查，不是基础构建输入 |
| 部分旧调查/迁移/实例准备工具 | 含机器路径或实例操作，另行参数化后再公开 |

这些文件不删除。若以后公开某份报告，应先核路径、身份信息与过时结论，再加入允许清单。

## 安全和许可

prepare_repository.py 按 Git 规则生成候选清单，检查私钥、常见令牌、口令赋值、JWT、
机器绝对路径、符号链接与误带二进制。报告只给位置/类别，不回显秘密值。
启发式扫描不保证发现所有秘密；提交前仍需查看实际差异。第三方依赖不提交，保留许可/署名。
当前新增内容仍为保留所有权利，不自动改成开源许可证。
Forge MDK原许可原文单独保留于docs/third-party/forge-mdk/LICENSE.txt，由LICENSE.md和第三方说明明确其适用范围。
根目录模板LICENSE.txt与README.txt均不在公开允许清单，README.txt仍可留本地查阅。

## 提交前

运行候选检查及干净副本构建，再查看 git status 和暂存差异。不用 git add -f 绕过规则。
已经被跟踪的文件不会因为新增忽略规则自动退出跟踪。准备工具不操作现有暂存区或远程仓库。
